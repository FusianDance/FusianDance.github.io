# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Website for Fusian Dance Crew, deployed to GitHub Pages at https://fusiandance.github.io. React Router 8 (framework mode) on Vite 8, React 19, TypeScript 6, Tailwind CSS v4, shadcn/ui (base-vega style on Base UI, lucide icons), ESLint + Prettier.

## Commands

```bash
npm run dev            # dev server
EDIT_TARGET=local npm run dev   # edit mode target: browser (dev default, Save only in the browser) | local (Save writes working tree) | <branch> | main
npm run build          # prerender to build/client/
npm run typecheck      # react-router typegen && tsc (CI runs this)
npm run lint           # eslint
npm run format         # prettier --write (format:check in CI)
FEATURES=audition npm run build   # override data/pages.yml (comma-separated enabled pages; works for dev too)
node --test "scripts/*.test.mjs"   # self-check for src/lib/content.ts
```

The only tests are `scripts/*.test.mjs`. CI (`.github/workflows/build.yml`) runs them, lint, format check, typecheck, and build on PRs.

TypeScript is pinned to 6.0.x because typescript-eslint doesn't support TS 7 yet.

## Architecture

**Static prerender only.** `react-router.config.ts` sets `appDirectory: "src"`, `ssr: false`, `prerender: true`: every route in `src/routes.ts` is rendered to `build/client/<route>/index.html` at build time. No server runtime: route `loader`s only run at build time, so anything that must change without a redeploy has to be fetched client-side. `npm run build` copies the SPA fallback to `404.html` for GitHub Pages.

**Content lives in `data/*.yml`, not in code.** `src/lib/data.server.ts` reads `announcements.yml`, `insta-posts.yml`, `contact.yml` and `pages.yml` with `fs`; the `.server` suffix makes React Router refuse to bundle it for the client, so import it only from route `loader`s (`src/root.tsx` loads `contact` for the footer). Components get the data via `loaderData` props. Anything that depends on the current time (past/upcoming split) uses `useNow(buildTime)` from `src/lib/hooks/use-now.ts`, with `buildTime` returned by the loader: it renders with the build time (matching the prerendered HTML) and switches to the real time after mount. Announcement `startDate` and optional `endDate` are ISO 8601 with offset (`allDay: true` shows dates only, `endDate` is then the last day); an announcement is past once its end (else start; for all-day events the midnight after) has passed, so a running event stays upcoming. Dates are formatted with `timeZone: "Europe/Berlin"` so build and browser agree. Instagram posts are stored as canonical post URLs only; `PostCard` builds the embed HTML from them, so `data.server.ts` rejects any URL that isn't `https://www.instagram.com/(p|reel)/<id>/`.

**Edit mode.** The only writer of `data/*` and `public/uploads/` besides hand edits. `src/lib/edit/` holds it, layered like ports and adapters: the UI imports only `session.ts` (the core: state, use cases, hooks, and re-exports of login and deploy status) and `target.ts` (mode constants and texts); behind the core sit the `ContentStore` implementations, `auth.ts` (login per target, `useLoggedIn`; the GitHub token never reaches the UI), `deploy.ts` and `storage.ts` (guarded browser storage). `session.ts` keeps the state (`draft`, `saved`, `preview`) in memory (typing writes no storage), read via `useSyncExternalStore` so prerendered HTML is unaffected; `files.ts` has the `Draft` type, the `FILES` list, loading/serializing (`loadFiles`, `changes`, `savedAfter`) and `problem` (validation). `save()` hands the draft to a `ContentStore` (`load()`, `save(draft, saved)`, interface in `files.ts`) picked at build time from the target: `githubStore` (`github-store.ts`; `main` in production) talks to the GitHub API from the browser and commits all changed files as one commit (Git Data API, non-forced ref update, blob-sha check so concurrent edits are refused, never overwritten), `localStore` and `browserStore` are described below. Unsaved edits survive reloads, the login trip to Google and closing the tab: when the page is left or hidden (`beforeunload`, `pagehide`, `visibilitychange` to hidden) they are backed up to localStorage (`fusian-edit-draft`) together with the saved state they are based on and the target. `startSession` loads the store's saved state and restores the backup on top as unsaved changes only if its saved file shas and target match, else drops it. Only Save, Discard and Log out remove the backup (a tab without edits never deletes another tab's); with two tabs holding unsaved edits the last one left wins. The browser's "Leave site?" prompt only appears when the backup didn't fit into localStorage (many big photos). The login token stays in localStorage (`auth.ts`). Login: the footer button sends the browser to Google's OAuth account picker (`response_type=id_token`, client `GOOGLE_CLIENT_ID`, redirect to `/` with `state` checked against sessionStorage); `finishLogin()` POSTs the ID token to the Apps Script web app in `apps-script/Code.gs` (owned by the crew Google account, "Execute as: Me", "Anyone"), which verifies it via Google's tokeninfo (audience = `CLIENT_ID`), checks the email against its `ALLOWED_EMAILS` script property, and answers with a 1h GitHub App installation token. Allowed redirect URIs are configured on the OAuth client in Google Cloud Console; setup and troubleshooting are in `docs/edit-mode-setup.md`. While editing, the navbar gets a Contact entry (`/edit/contact`, edit-only page). `useEditDraft` (edit mode only) makes `/events`, `/gallery`, `/about` and `/audition` render the editors in `src/components/edit/`; `useDraft` (any session) plus `useLiveContent` show the draft in the normal pages (Preview). `EditBar` (mounted in `root.tsx`) floats icon buttons with tooltips: Log out (or Log in when the token expired) on the left, Discard changes (resets the draft to the last saved state), an Edit/Preview toggle group and Save on the right. While an edit session exists, `useDeploy` in `src/lib/edit/deploy.ts` polls the latest `deploy.yml` run on `main` (after Save: the run of the saved commit) without auth, since the edit token can only touch file contents (public repo, 60 requests/h per IP, so it only polls every 20s while a run is pending), and the bar shows a deploying or failed line. The about and audition pages are `data/about.md` and `data/audition.md` (audition keeps its Google Form embed in code below the Markdown), rendered by `src/components/markdown.tsx` (react-markdown + remark-gfm, raw HTML off) and edited in a CodeMirror 6 editor with an Obsidian-style live preview (`markdown-editor.tsx`, `MarkdownEditor`, lazy-loaded so visitors don't download it): the text stays raw Markdown (lossless), and a view plugin hides its syntax, draws bullets and shows images everywhere except on the lines the cursor is on. The renderer styles via the `.rich-text` class in `app.css`; the editor mirrors headings and notes with Tailwind line classes, so keep the two in step. Photos dropped, pasted or added in either editor are inserted as `![alt](/uploads/<name>.jpg)`, shrunk to JPEG and kept as data URLs in `draft.uploads` until Save uploads them as git blobs to `public/uploads/`. YAML writes go through `toYaml` in `src/lib/content.ts`, which keeps the files' header comments; `data/` is in `.prettierignore` so Prettier doesn't fight its output. `src/lib/content.ts` also holds the validation shared with the build (`toAnnouncements`, `toPosts`) and must only use relative imports, since `scripts/content.test.mjs` runs it with plain node. `EDIT_TARGET` (`vite.config.ts`, exposed as `TARGET` in `target.ts`) picks the target at build time, so production only bundles the GitHub store: builds are always `main` (any other value fails the build); `vite.config.ts` sets `optimizeDeps.entries` to all `src/**/*.tsx` so Vite finds every dependency up front (otherwise it re-bundles and reloads the page on the first visit of a page); `npm run dev` defaults to `browser`, which loads `data/` from the working tree through a dev-only middleware (`/__edit/...`, `apply: "serve"`), skips Google login (Log in just enters edit mode) and `browserStore` Save only keeps the draft in localStorage (`fusian-edit-browser`, written only by Save, separate from the unsaved backup; Discard goes back to it, no files change); `local` (`localStore`, blob-sha conflict check shared with GitHub) is the same but Save PUTs the changed `data/<name>.yml|md` and `public/uploads/<name>` files into the working tree (the middleware refuses writes in any other mode and other paths); any other value is a GitHub branch name (must be pushed) with real login, loads and commits go to that branch and there is no deploy line since only `main` deploys; `EDIT_TARGET=main npm run dev` is the old live behaviour, explicit only. `browserStore` starts from the working tree and drops its saved copy when the local files' blob shas differ from the ones it started from (checkout/pull/hand edits; a dev-server restart alone keeps it). While the target isn't `main`, `TARGET_NOTE` shows as a red banner above the navbar (`navbar.tsx`) and is repeated in the edit bar. A commit to `main` triggers `deploy.yml`, which calls `build.yml` and publishes `build/client/` to Pages.

**Feature flags.** Page flags live in `data/pages.yml` (page key → true/false), read by `pages` in `src/lib/data.server.ts`; the env var `FEATURES=audition,other` (comma-separated enabled keys, `FEATURES=` = none) overrides the file locally. Flaggable pages are registered in `FlaggedPages` in `src/lib/models/nav-item.ts` (key, navTitle, appRoute, file); to add one, add an entry there and its key in `data/pages.yml`. `src/routes.ts` adds the routes of enabled pages only, so disabled pages aren't bundled or prerendered, in dev too. The root loader hands the enabled keys to `Navbar`. In edit mode the navbar shows every flagged page with an on/off button; flipping it changes `data/pages.yml` in the draft (`draft.pages`), Save commits it and the push to `main` redeploys (the deploy status line shows progress). Git remembers the flags: no repo variable or workflow input.

**SEO.** Every page route exports `meta` built with `seo()` from `src/lib/seo.ts` (unique title and description, canonical URL with trailing slash as GitHub Pages serves it, Open Graph tags). The home page adds `DanceGroup` JSON-LD from the contact data; keep it in line with what the site shows. Edit-only pages get `robots: noindex`. A new page needs its own `meta`, otherwise it inherits the root fallback.

**Layout.** `src/root.tsx` is the HTML shell (`Layout`) and wraps every page with `ThemeProvider` (next-themes, class-based, works outside Next), `Navbar`, and `Footer`; its `ErrorBoundary` renders 404s. Use `Link` from `react-router` for internal links, plain `<a>` for external ones. shadcn primitives are in `src/components/ui/`; add new ones via `npx shadcn@latest add` (`components.json` aliases use `@/`).
